# LightLang Persistent Bytecode Format (.lbc)

## Purpose

A LightLang source program can be compiled once, saved as `.lbc`, and later executed by
the VM without loading or parsing the original `.lw` source.

## Version 2

Stage 8 writes:

    LIGHTLANG_BYTECODE 2
    COUNT <number-of-instructions>

Each instruction record has the form:

    <opcode> <target> <source-line> "<data-type>" "<operand>"

The quoted fields use C++ quoted-string escaping, preserving spaces, quotes,
backslashes, tabs, and escaped string data.

Example function-capable records:

    PUSH_INT 0 8 "" "5"
    CALL 12 8 "1" "factorial"
    STORE_TEMP 0 8 "" "%t1"
    HALT 0 0 "" ""
    BIND_PARAM 0 1 "int" "n"
    ...
    RETURN 0 3 "int" ""
    HALT 0 0 "" ""

For CALL, `target` stores the function entry address, `data-type` stores the argument
count, and `operand` stores the function name for inspection/diagnostics. For RETURN,
the `data-type` field stores the declared function return type.

## Version compatibility

The Stage 8 loader accepts:
- version 2 files generated by the current compiler;
- version 1 files generated by Stage 7.

The writer always emits version 2.

## Loader validation

Before execution, the loader checks:
- LightLang file signature;
- supported bytecode version;
- declared instruction count;
- instruction-record syntax;
- recognized opcodes;
- non-negative source-line metadata;
- supported DECLARE/BIND_PARAM/RETURN types;
- valid jump and CALL targets;
- valid CALL argument counts;
- final HALT termination;
- absence of unexpected trailing content.
